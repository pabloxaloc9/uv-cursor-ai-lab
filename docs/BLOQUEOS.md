# Resolver bloqueos sin perder el taller

| Situación | Acción concreta |
|---|---|
| No aparecen los roles | Abrir la raíz del repo y adjuntar el archivo del rol al chat principal. No hace falta un subagente nativo |
| No aparecen las skills | Adjuntar su SKILL.md; no instalar un paquete externo con nombre parecido |
| Cursor ignora una decisión | Adjuntar cuaderno y requisito relevante; pedir que identifique el conflicto antes de seguir |
| No acepta imágenes | El equipo describe las referencias; registrar análisis visual limitado |
| Se agota la cuota | Guardar trabajo, comprobar cuentas propias disponibles y seguir la guía Free. No repetir prompts ni compartir credenciales |
| Git pide iniciar sesión | Hacer el acceso normal con la cuenta propia; nunca pegar contraseñas o tokens en Agent. Se puede continuar localmente y subir después |
| No hay runtime para el stack propuesto | Volver a comparar viabilidad; elegir con el equipo una opción disponible o preparar el runtime oficial con ayuda del profesor |
| No arranca al minuto 35 | Mostrar comando y error, sin secretos; pedir diagnóstico mínimo. Reducir dependencias o complejidad con decisión registrada |
| Puerto ocupado | Detener solo el proceso propio o elegir otro puerto. Registrar el cambio; el almacenamiento del navegador puede depender del origen |
| Desaparecen datos al recargar | Revisar guardado y carga inicial. Un array en memoria no es persistencia; guardar un ejemplo ficticio y volver a probar |
| El navegador muestra contenido antiguo | Comprobar URL, proceso y recarga. No borrar datos o cachés ajenos como primer remedio |
| Cambia todo el diseño al corregir | Adjuntar sección 3 y pedir un cambio mínimo, conservando los tokens y componentes acordados |
| La IA dice que está probado, pero no hay evidencia | Pedir comando/salida o pasos observados. Si no existen, marcar NO PROBADO y comprobarlo |

Cuando comuniques un error, utiliza datos ficticios y pasos reproducibles. [Plantilla de error](../plantillas/ERROR.md).
